# Delhivery Last-Mile Delay Intelligence Pipeline

## 1. Project Overview

The **Delhivery Last-Mile Delay Intelligence Pipeline** is a machine learning project designed to analyze shipment delivery performance, predict delivery times, identify potentially delayed shipments, and discover operational segments associated with higher delay rates.

The project uses synthetic shipment data to demonstrate an end-to-end data science workflow, including data generation, data cleaning, exploratory data analysis (EDA), regression, classification, operational segmentation, model packaging, and batch prediction.

### Project Objectives

- Clean and validate shipment and hub data.
- Explore shipment delivery times and delay patterns.
- Predict delivery time in hours using regression models.
- Classify shipments as on time or potentially delayed.
- Identify high-risk operational segments using service type, hub tier, and distance.
- Package trained models for reuse.
- Generate predictions for new shipments.

**Data privacy:** This project uses synthetic data and is intended for educational and portfolio purposes. The dataset does not represent actual Delhivery operational records.

## 4. Dataset Description

The project uses three primary input datasets:

| Dataset | Description |
|---|---|
| `raw_shipments.csv` | Synthetic historical shipment records containing shipment details, delivery times, and data quality issues. |
| `hubs.csv` | Hub information, including city, region, hub tier, and daily capacity. |
| `new_shipments.csv` | 48 new synthetic shipment records used to demonstrate prediction. |

The pipeline creates `modelling_table.csv`, which contains cleaned shipment data, hub attributes, engineered features, and the target variables.

### Important Features

The model uses 17 features:

- Promised delivery hours
- Distance in kilometres
- Parcel weight
- Log-transformed declared value
- Number of stops
- Rain indicator
- Sale-event indicator
- Cash-on-delivery indicator
- Weekend indicator
- Dispatch hour
- Hub tier
- Hub daily capacity
- Label-print batch
- Scanner build number
- Tape-roll number
- Sticker serial number modulo
- Shelf-slot number

### Target Variables

**Regression target:** `delivery_hours`

Predicts the number of hours required for delivery.

**Classification target:** `is_delayed`

- `1`: Delivery time exceeds the promised delivery window.
- `0`: Delivery time does not exceed the promised delivery window.

Promised delivery windows are defined as follows:

| Service type | Promised hours |
|---|---:|
| Express | 36 |
| Standard | 60 |
| Economy | 96 |

## 5. Project Methodology

### Part A: Data Cleaning and Exploratory Data Analysis

Script: `part_a_clean_eda.py`

The first stage prepares the data for analysis and modelling.

Key operations:

- Removes duplicate shipment records.
- Standardizes service-type labels.
- Handles missing payment-mode values.
- Cleans declared values containing currency symbols and commas.
- Converts dispatch timestamps to datetime values.
- Identifies invalid parcel weights and treats them as missing.
- Imputes missing numerical values using medians.
- Merges shipment records with hub information.
- Engineers model features and creates the delay target.
- Analyzes delivery-time distributions, outliers, correlations, and group delay rates.

Generated outputs:

- `outputs/part_a_checks.csv`
- `outputs/part_a_delay_by_group.csv`
- `outputs/part_a_correlations.csv`
- `data/modelling_table.csv`

### Part B: Delivery-Time Regression

Script: `part_b_regression.py`

The regression stage predicts delivery time in hours.

The dataset is divided into training, validation, and test sets:

| Split | Records | Percentage |
|---|---:|---:|
| Training | 840 | 70% |
| Validation | 180 | 15% |
| Test | 180 | 15% |
| Total | 1,200 | 100% |

The split uses `random_state=42`. Feature scaling is fitted on training data only.

Models evaluated:

- Mean baseline
- Linear Regression
- Decision Tree Regressor
- Random Forest Regressor
- Gradient Boosting Regressor

The workflow also includes decision-tree depth diagnostics, gradient-boosting learning-rate experiments, and five-fold cross-validation for the two best validation candidates.

**Evaluation metrics:** MAE, MSE, RMSE, and R².

The final model is selected using validation RMSE and evaluated on the test set.

Generated outputs:

- `outputs/part_b_checks.csv`
- `outputs/part_b_tree_depth.csv`
- `outputs/part_b_metrics.csv`
- `outputs/part_b_gb_learning_rate.csv`
- `outputs/part_b_cv.csv`

### Part C: Shipment Delay Classification

Script: `part_c_classification.py`

This stage predicts whether a shipment is likely to exceed its promised delivery window.

Models evaluated:

- Logistic Regression
- Decision Tree Classifier
- Random Forest Classifier
- Gradient Boosting Classifier

The classification workflow uses a reproducible, stratified training/validation/test split. Candidate models are compared on validation data, and the classification threshold is tuned using validation F1-score.

A threshold of `0.35` was selected from the tested thresholds. The selected classifier is then evaluated on the held-out test set.

**Evaluation metrics:** Accuracy, precision, recall, F1-score, and ROC-AUC.

Generated outputs:

- `outputs/part_c_metrics.csv`
- `outputs/part_c_thresholds.csv`
- `outputs/part_c_confusion_matrix.csv`
- `outputs/part_c_classification_report.csv`

### Part D: Operational Segmentation

Script: `part_d_segments.py`

This stage identifies shipment segments with higher observed delay rates.

Segments are analyzed by:

- Service type
- Hub tier
- Distance band
- Combined service type, hub tier, and distance band

The analysis calculates shipment counts, delayed shipment counts, delay rates, and mean delivery times.

Generated outputs:

- `outputs/part_d_segment_summary.csv`
- `outputs/part_d_combined_segments.csv`
- `outputs/part_d_risk_ranking.csv`

### Model Packaging

Script: `package_model.py`

The packaging stage trains and saves the final models using all 1,200 labelled historical records.

Generated files:

- `models/delivery_time_model.joblib`
- `models/delay_classifier.joblib`
- `models/model_config.json`

The configuration stores the feature order, model filenames, classification threshold, delay definition, and promised delivery windows.

The packaged models are retrained on the full labelled dataset after model evaluation. They are therefore separate from the fitted models used for the held-out test metrics.

### Prediction Pipeline

Script: `predict_delay.py`

The prediction pipeline:

1. Loads the saved models and configuration.
2. Reads new shipment records and hub information.
3. Cleans incoming data using medians calculated from the historical shipment dataset.
4. Builds the required model features.
5. Predicts delivery time in hours.
6. Calculates the probability of delay.
7. Classifies shipments using the configured threshold.
8. Saves the results to `outputs/predictions.csv`.

## 6. Results

### 6.1 Data Cleaning and EDA

| Metric | Result |
|---|---:|

The data preparation process reduced 1,224 raw records to 1,200 unique shipment records. Missing values in the model features and target variables were resolved.

### 6.2 Regression Results

Validation performance:

| Model | Validation RMSE | Validation R² |
|---|---:|---:|
| Linear Regression | 4.8912 | 0.9313 |
| Gradient Boosting | 4.9165 | 0.9306 |
| Random Forest | 5.4680 | 0.9141 |
| Decision Tree | 6.2796 | 0.8867 |
| Mean Baseline | 18.8552 | -0.0212 |

Linear Regression achieved the lowest validation RMSE among the evaluated candidates.

**Final test result:**

- Test RMSE: **4.5235 hours**

This measures the root mean squared prediction error on the held-out test set. It does not guarantee that every shipment prediction will be accurate to within 4.52 hours.

Cross-validation produced the following mean R² results for the top two validation candidates:

| Model | Mean CV R² | Standard deviation |
|---|---:|---:|
| Linear Regression | 0.9261 | 0.0048 |
| Gradient Boosting | 0.9352 | 0.0044 |

Gradient Boosting had the higher mean cross-validation R², while Linear Regression remained the final selection under the validation-RMSE criterion.

### 6.3 Classification Results

The selected classifier was Gradient Boosting.

Validation performance at the default threshold of 0.50:

| Metric | Result |
|---|---:|
| Accuracy | 93.33% |
| Precision | 89.47% |
| Recall | 80.95% |
| F1-score | 85.00% |
| ROC-AUC | 97.29% |

The threshold-tuning experiment selected `0.35`, which achieved a validation F1-score of 87.36%.

Held-out test performance at the selected threshold:

| Metric | Test result |
|---|---:|
| Accuracy | 83.89% |
| Precision | 62.50% |
| Recall | 73.17% |
| F1-score | 67.42% |
| ROC-AUC | 91.16% |

Test confusion matrix:

| Actual outcome | Predicted on time | Predicted delayed |
|---|---:|---:|
| On time | 121 | 18 |
| Delayed | 11 | 30 |

The threshold of 0.35 identifies shipments as potentially delayed when their predicted probability of delay is at least 35%. This threshold was selected using validation data, not test data.

Observed delay rates across the 1,200 historical synthetic shipments:

| Segment | Shipments | Delay rate |
|---|---:|---:|
| Express | 243 | 48.97% |
| Standard | 642 | 20.56% |
| Economy | 315 | 8.57% |
| Hub Tier 1 | 400 | 4.00% |
| Hub Tier 2 | 400 | 21.50% |
| Hub Tier 3 | 400 | 44.00% |
| Distance 0–200 km | 274 | 2.19% |
| Distance 201–400 km | 563 | 13.68% |

The results show substantially higher observed delay rates for longer-distance shipments, Tier 3 hubs, and Express shipments.

The highest-risk combined segments included:

- Express shipments handled by Tier 3 hubs over 601 km: 11 of 11 shipments delayed.
- Express shipments handled by Tier 2 hubs over 601 km: 7 of 7 shipments delayed.
- Standard shipments handled by Tier 3 hubs over 601 km: 33 of 37 shipments delayed.

The first two combined segments have small sample sizes. Their observed 100% delay rates should be treated as investigation priorities rather than reliable estimates of future performance.

## 10. Business Recommendations

Based on the observed patterns in the synthetic dataset:

1. **Investigate long-distance shipments:** Review routes, transit connections, handover processes, and promised delivery windows for shipments exceeding 600 km.
2. **Review Tier 3 hub operations:** Examine hub capacity, dispatch backlogs, staffing, and transfer processes.
3. **Monitor Express shipments:** Investigate performance on longer routes and at higher-risk hubs.
4. **Introduce delay-risk monitoring:** Use predicted delay probabilities to prioritize shipments for operational review.
5. **Monitor segment sample sizes:** Evaluate both shipment counts and delay rates before making operational decisions.
6. **Track model performance over time:** Compare predictions with actual outcomes when verified delivery data becomes available.

These recommendations are based on observed associations. They do not establish that any particular operational factor causes delays.

## 11. Limitations

- The project uses synthetic data and does not demonstrate performance on real Delhivery shipment records.
- Observed relationships may reflect the assumptions built into the synthetic data-generation process.
- Test-set performance is an estimate based on one held-out split and may differ on future data.
- The classification threshold was selected to maximize F1-score among the tested validation thresholds. A production threshold should also consider the relative costs of missed delays and false alarms.
- Small operational segments may have unstable delay-rate estimates.
- The packaged models were retrained on the full labelled dataset and require separate evaluation if used in a new deployment.
- Real-world deployment would require monitoring, retraining procedures, data validation, access controls, and evaluation against actual delivery outcomes.

The Delhivery Last-Mile Delay Intelligence Pipeline demonstrates an end-to-end machine learning workflow using synthetic shipment data.

The project covers data cleaning, exploratory analysis, delivery-time regression, delay classification, operational segmentation, model packaging, and prediction for new shipments.

The regression and classification models provide a foundation for exploring delivery-time estimates and delay-risk prioritization, while the segmentation outputs translate the analysis into potential operational investigation areas.
